# 自動版號標記（SemVer Tagging）

本技能旨在為 `main`（或 `master`）主分支的合併節點依據語意化版本（Semantic Versioning / SemVer 2.0.0）規範打上版本標籤（Tag）。

## 什麼時候觸發此技能？

1. 當使用者輸入 `/agy-github-flow:tag`。
2. 當使用者要求「打 tag」、「標記版本」、「自動判斷版號」時。

## 執行的實作步驟

### 步驟 0：工作區狀態檢查（防越界機制）

1. 執行 `git status --untracked-files=no --porcelain` 檢查工作區是否乾淨。
2. 若偵測到有已追蹤檔案之未暫存或已暫存的修改（工作區非乾淨狀態）：
   - **必須立即中止流程**，嚴格禁止在本技能內自行拼湊或執行原生 `git add` 或 `git commit` 指令，亦嚴格禁止詢問使用者是否代為提交。
   - 明確提示使用者：「偵測到工作區尚有已追蹤檔案之未提交變更。打標籤前工作區必須保持乾淨，避免拉取最新節點時發生衝突。請先使用 `/agy-github-flow:commit` 完成正規提交流程後再進行標記。」
   - 注意：未追蹤檔案（Untracked files）不阻擋標記流程。

### 步驟 1：防呆機制（Branch Guard）與標籤同步

1. 若專案設定有遠端儲存庫（`git remote`），先執行 `git fetch --all --tags --prune` 確保本機取得遠端所有的標籤與提交歷史。
2. 執行 `git branch --show-current` 檢查當前分支。
3. 若當前分支不是 `main` 或 `master`：
   - **必須立即中止流程**，並告知使用者：「標記版本號必須在 main 主分支上執行，請先切換至 main 分支。」
   - **嚴格防越界規範**：嚴格禁止在此處詢問使用者是否代為切換分支或代為提交。
4. 若主分支落後遠端，先執行 `git pull --ff-only` 確保本地主分支為最新狀態。

### 步驟 2：檢查手動指定版號

1. 若使用者在呼叫技能時明確提供版號（例如：`/agy-github-flow:tag v1.2.3`）。
2. 直接跳過後續的 SemVer 分析，使用指令 `git tag <手動版號>` 在最新節點打上標籤，並提示使用者推播（`git push --tags`），結束流程。

### 步驟 3：找出未標籤的提交節點（支援 Merge/Squash/Rebase 與初版發布）

1. 執行 `git describe --tags --abbrev=0` 查詢上一個最新 Tag。若指令失敗或無輸出，代表儲存庫尚無任何標籤（初始版本發布）。
2. 若存在上一個 Tag：
   - 使用 `git log <上一個Tag>..HEAD --oneline` 比對自上一個標籤以來的所有新提交（完全相容 Merge Commit、Squash Merge、Rebase Merge 以及主分支一般提交）。
   - 若無任何新提交（輸出為空）：告知使用者「目前主分支所有提交皆已打過標籤，無需重複標記」，結束流程。
   - 若新提交中包含多個合併節點（`git log <上一個Tag>..HEAD --merges` 多於 1 筆）：進入步驟 4 詢問使用者範圍。
   - 若為單一合併節點或 Squash / Rebase 產生之常規提交：直接以最新節點（HEAD）為基準進入步驟 5 進行版號計算。
3. 若尚無任何標籤（初始版本發布）：
   - 執行 `git log HEAD --oneline` 取得專案全域提交歷史。
   - 預設初始版號為 `v1.0.0`（或參考 `package.json` 中的 `version` 加上 `v` 前綴，初期原型亦可為 `v0.1.0`）。
   - 直接進入步驟 6，以最新提交（HEAD）打上初始標籤。

### 步驟 4：處理多個未標籤節點（ask_question）

1. 若只有一個未標籤的合併節點，直接進入第五步。
2. 若有多個未標籤的合併節點，使用 `ask_question` 工具向使用者確認範圍：

   ```json
   {
     "questions": [
       {
         "question": "發現多個未標籤的合併節點，請問要標籤哪種範圍？",
         "options": [
           "(Recommended) 僅把最近的一次合併節點打上版本號",
           "全部的合併節點都要打上標籤"
         ],
         "is_multi_select": false
       }
     ],
     "toolSummary": "確認標籤範圍",
     "toolAction": "詢問要標籤幾個合併節點"
   }
   ```

### 步驟 5：版號判斷（SemVer 2.0.0）

針對目標提交節點（範圍內之提交紀錄）：
1. 分析變更範圍內的提交歷史（`<上一個Tag>..HEAD` 或初始提交）：
   - MAJOR（X.y.z）：當有不相容的 API 變更、破壞性變更（BREAKING CHANGE 或 `feat!:`, `fix!:` 等）時遞增。
   - MINOR（x.Y.z）：當加入向下相容的新功能（`feat:`）時遞增。
   - PATCH（x.y.Z）：當加入向下相容的錯誤修正（`fix:`）、優化（`perf:`）或重構（`refactor:`）時遞增。
2. 若存在上一個 Tag，以該版號進行遞增加算；若為初次發布，以預設初始版號（如 `v1.0.0`）為基準。
3. 最終產出的版號必須加上 `v` 前綴（例如 `v1.3.0`）。

### 步驟 6：執行標記與推播提示

1. 對於新版號，執行 `git tag <版號> <目標節點的 hash>`（若為最新提交亦可使用 HEAD）。
2. 執行完成後，向使用者總結打上的 Tag，並從技能列表中讀取並執行 `agy-github-flow:push`（或 `push`）技能，將標籤同步至遠端。

## 嚴格禁止事項（Anti-patterns）

1. **嚴格禁止執行原生 `git commit` 指令**：本技能完全不包含提交程式碼的功能。
2. **嚴格禁止跨技能越界代理提交**：當工作區不乾淨或處於非主分支時，必須直接中斷並向使用者明確說明，嚴格禁止自行詢問代為提交或私自執行 git 提交指令。
